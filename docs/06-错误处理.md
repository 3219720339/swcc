# 06 错误处理

状态：规范基线

## 1. 编译期诊断

- 编译器错误带源码位置（文件、行、列）、错误级别（error/warning）和消息。
- 一次编译输出全部可发现的错误，不因第一个错误停止（词法/语法/语义各阶段尽可能收集）。
- 检查通过的标准：无 error，warning 不阻断编译（严格模式可配置）。

## 2. 运行期异常

```js
function risky(): void {
    throw new Error("something failed");
}

try {
    risky();
} catch (e: Error) {
    println(e.message);
} finally {
    cleanup();
}
```

规则：

- `throw` 的值必须是 `Error` 类实例或 `string`。
- `catch (e)` 不写类型捕获所有异常；`catch (e: HttpError)` 只捕获匹配类型。
- 多个 `catch` 按源码顺序匹配；`finally` 无论是否异常都执行。
- 异常传播**不展开平台栈**：由运行时自带传播机制实现，跨函数/跨模块一致。
- 异常不能穿过 `extern c` 边界；C 边界函数若可能失败，应返回错误码或 `Result`（见下）。

## 3. Option 与 Result（标准库）

```js
import { Option } from "std/core";
import { Result } from "std/core";

function find(values: int[], target: int): Option<int> { ... }
function parse(text: string): Result<int, string> { ... }
```

- 缺失值用 `Option<T>`，可预期失败带原因用 `Result<T, E>`。
- 同一能力不得在多个模块用不同错误模型重复公开（统一由 `std/core` 定义）。
- `?` 传播运算符（从 `Result`/`Option` 提前返回）列入 v0.2。

## 4. 运行期错误分类

| 错误 | 触发 | 默认行为 |
|---|---|---|
| 越界 | `arr[i]` 越界、负数 | 抛异常（v0.2 可捕获） |
| 空值访问 | 对 `null` 用 `!` 或非空上下文 | 抛异常 |
| 除零/取余零 | 整数除零 | 抛异常 |
| 整数溢出 | 显式转换截断外、算术溢出 | Release 回绕，Debug 检查（v0.2 定案） |
| 分配失败 | 内存不足 | 终止程序 |

## 5. defer 与清理

```js
function readFile(path: string): string {
    const file = std.fs.open(path);
    defer file.close();
    return file.readAll();
}
```

- `defer` 在当前作用域退出时按逆序执行，保证异常路径同样清理。
- 引用类型变量的释放由引用计数保证，不需要 `defer`；`defer` 用于非托管资源（文件句柄等）。
