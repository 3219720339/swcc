# 06 错误处理

状态：规范基线

## 1. 编译期诊断

- 编译器错误带源码位置（文件、行、列）、错误级别（error/warning）和消息。
- 一次编译输出全部可发现的错误，不因第一个错误停止（词法/语法/语义各阶段尽可能收集）。
- 检查通过的标准：无 error，warning 不阻断编译（严格模式可配置）。

## 2. 运行期异常

```js
function risky(): void {
    throw "something failed";
}

try {
    risky();
} catch (e: string) {
    println(e);
} finally {
    cleanup();
}
```

规则：

- `throw` 的值必须是 `string` 或 class 实例；当前没有内建 `Error` / `HttpError` 类。
- `catch (e)` 不写类型捕获所有异常；`catch (e: string)` 捕获字符串异常，
  `catch (e: SomeClass)` 按类类型匹配。
- 多个 `catch` 按源码顺序匹配；`finally` 无论是否异常都执行。
- 异常传播**不展开平台栈**：由运行时自带传播机制实现，跨函数/跨模块一致。
- 异常不能穿过 `extern c` 边界；C 边界函数若可能失败，应返回错误码或 `Result`（见下）。

## 3. Result（标准库，已实现）

```js
import { Result } from "std/result";

function parse(text: string): Result<int, string> { ... }
```

- `Result<T, E>` 定义为 `Ok(T)` / `Err(E)` 两个变体；可预期失败可由调用方用
  `match` 处理。
- `expr?` 已实现：操作数和当前函数返回值都必须是含单一 `Ok` / `Err` payload 的
  Result 形枚举，错误 payload 可赋值给函数返回值的 `Err` payload 时提前返回。
- 当前标准库未提供 `Option<T>`；可空引用使用 `T?` 与 `null` 表达缺失值。

## 4. 运行期错误分类

| 错误 | 触发 | 默认行为 |
|---|---|---|
| 越界 | `arr[i]` 越界、负数 | 运行时错误 |
| 空值访问 | 对 `null` 用 `!` 或非空上下文 | 抛异常 |
| 除零/取余零 | 整数除零 | 抛异常 |
| 整数溢出 | 显式转换截断外、算术溢出 | Release 回绕，Debug 检查（v0.2 定案） |
| 分配失败 | 内存不足 | 终止程序 |

## 5. defer 与清理

- `defer` 已实现：正常作用域退出、`return`、`break`、`continue` 与异常传播都会按 LIFO
  顺序执行仍活跃的清理表达式。
- 引用类型由保守式 GC 管理；文件、socket、HTTP 会话和进程句柄是非托管资源，当前必须由
  调用方显式调用对应 `close` 函数。
