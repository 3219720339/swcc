# 09-发布与分发（v0.1.2）

> 本文档说明如何构建、验证与分发各平台「解压即用」SDK，以及发布 0.1.x 版本的
> 固定流程。所有步骤都可在仓库根目录执行；产物统一放进 `dist/`（已 gitignore）。

## 一、Windows x64 SDK（自包含，无需任何外部工具链）

### 1. 目录结构

```
swc-windows-x64/
├── swc.exe                  # 编译器本体
├── version.txt              # 版本号（取自根 Cargo.toml）
├── bin/
│   ├── ld.lld.exe           # 链接器
│   ├── libLLVM-22.dll       # 运行时依赖（swc.exe 加载）
│   ├── libc++.dll
│   └── libunwind.dll
├── lib/
│   ├── libucrt.a            # UCRT 静态库（-lucrt）
│   ├── libucrtbase.a        #        （-lucrtbase）
│   ├── libkernel32.a        #        （-lkernel32）
│   ├── libshell32.a         #        （-lshell32）
│   ├── libole32.a           #        （-lole32）
│   ├── libws2_32.a          #        （-lws2_32）
│   ├── libclang_rt.builtins-x86_64.a   # compiler-rt
│   ├── runtime.obj          # 预编译运行时（runtime.c）
│   ├── runtime_asm.obj      # 预编译运行时（runtime_x64.S）
│   └── startup.obj          # 预编译启动代码（startup.s）
└── stdlib/                  # 全部标准库 .sw 模块
```

> **重要**：`lib/` 必须包含编译器固定链接的 6 个静态库（ucrt / ucrtbase /
> kernel32 / shell32 / ole32 / ws2_32）+ builtins。曾出现过 `make-sdk.py`
> 漏拷 `libole32.a` 与 `libws2_32.a` 导致分发版链接网络/COM 相关程序失败，
> 已在 0.1.2 修复并加了存在性检查（缺失即报错退出）。

### 2. 使用（解压即用）

```pwsh
# 解压 zip 到任意目录，然后：
cd <解压目录>/swc-windows-x64
./swc.exe build hello.sw -o hello.exe   # 编译（自动定位旁边 bin/ lib/ stdlib/）
./hello.exe                              # 运行
```

无需安装 Rust、llvm-mingw、clang 或设置任何环境变量（`SW_TOOLCHAIN` /
`SW_STDLIB` / `SW_RUNTIME` 均可省略；显式设置时会优先于 SDK 自带文件）。

### 3. 构建

本机（Windows）推荐用 Python 版本（与 CI 一致）：

```pwsh
python tools/make-sdk.py "D:\llvm-mingw-20260616-ucrt-x86_64" dist
# 产物：dist/swc-windows-x64-<版本号>.zip
```

无 Python 的机器可用 PowerShell 版本（功能等价，zip 为扁平布局）：

```pwsh
powershell -ExecutionPolicy Bypass -File tools/make-sdk.ps1 `
  -Toolchain "D:\llvm-mingw-20260616-ucrt-x86_64" -OutDir dist
```

### 4. 验证

构建后务必做「无外部工具链」冒烟（CI 已自动化，本机可手动复现）：

```pwsh
$zip = Get-ChildItem dist/swc-windows-x64-*.zip | Select-Object -First 1
$extract = Join-Path $env:TEMP 'sdk-smoke'
Expand-Archive -Path $zip.FullName -DestinationPath $extract -Force
$sdk = Join-Path $extract 'swc-windows-x64'
Remove-Item Env:SW_TOOLCHAIN, Env:SW_STDLIB, Env:SW_RUNTIME -ErrorAction SilentlyContinue
# 1) 联网能力探针（std/http → ws2_32/ole32）：编译链接验证 6 个库齐全
& "$sdk/swc.exe" build examples/probe-batch11.sw -o probe-b11.exe
# 2) 端到端：编译并运行 hello
& "$sdk/swc.exe" build examples/hello.sw -o hello.exe
& "$extract/hello.exe"
```

## 二、Linux / macOS SDK

- `tools/make-sdk-linux.py <llvm-mingw 目录> dist` → `dist/swc-linux-x64-<版本号>.tar.gz`
  （musl 静态链接 x86_64 + aarch64，解压即用）
- `tools/make-sdk-macos.py dist` → `dist/swc-macos-<版本号>.zip`
  （原生链接用系统 cc，无需工具链）

Linux/macOS SDK 不含 ole32/ws2_32（Windows 专用库），无此遗漏问题。

## 三、发布流程（0.1.x）

### 1. 版本号

只改根 `Cargo.toml` 的 `[workspace.package] version`（各 crate 用
`version.workspace = true` 继承，无需逐个改）。然后：

```pwsh
cargo metadata --no-deps --format-version 1   # 触发 Cargo.lock 同步
cargo build --release -p swc                  # 确认可编译
```

`Cargo.lock` 中 5 个 workspace 包（sw-common / sw-frontend / sw-semantic /
sw-codegen-cranelift / swc）的 `version` 会随之更新；若手工编辑务必保持
`cargo metadata` 报告一致。

### 2. 构建三平台 SDK

```pwsh
python tools/make-sdk.py       "D:\llvm-mingw-20260616-ucrt-x86_64" dist   # Windows
python tools/make-sdk-linux.py "D:\llvm-mingw-20260616-ucrt-x86_64" dist   # Linux（在 Linux 上跑）
python tools/make-sdk-macos.py dist                                        # macOS（在 macOS 上跑）
```

### 3. 校验和（可维护形式）

```pwsh
python tools/make-checksums.py dist              # 生成 dist/SHA256SUMS
python tools/make-checksums.py dist --check      # 校验（发布前必跑，返回 0 才发布）
python tools/make-checksums.py dist --version    # 只列出带版本号的产物
```

`SHA256SUMS` 为 GNU 风格（`哈希  相对路径`），随产物一起分发；用户可用
`sha256sum -c` 或脚本 `--check` 验证完整性。

### 4. 发布说明（release notes）

发布说明维护在 `docs/发布说明.md`（追加式，一个版本一节）。模板：

```markdown
## v0.1.2（YYYY-MM-DD）

### 新功能
- ...

### 修复
- ...

### SDK / 分发
- Windows SDK 补齐 libole32.a / libws2_32.a（此前分发版链接网络/COM 失败）
- CI 新增 SDK artifact 冒烟：解压 zip、无外部工具链编译联网能力探针
- 校验和工具 tools/make-checksums.py

### 已知限制
- 见「二、已知限制」/ README
```

### 5. 发布前检查清单

- [ ] `cargo test --workspace` 全绿
- [ ] 本机 + CI 三平台 examples 全过（`tools/run-examples.py`）
- [ ] `cargo fmt --all -- --check` 通过
- [ ] 三平台 SDK 构建成功
- [ ] Windows SDK 无外部工具链冒烟通过（CI 自动化）
- [ ] `tools/make-checksums.py dist --check` 返回 0
- [ ] 更新 `docs/发布说明.md`，标注版本号与日期
- [ ] 提交并推送 Gitee + GitHub（触发三平台 CI）
- [ ] CI 全绿后打 tag（如 `v0.1.2`），在 GitHub 上创建 Release 并附三个
      SDK 产物与 SHA256SUMS（人工操作，不在 CI 自动创建）

> 注：本仓库 CI 只构建/上传 Windows SDK artifact，不自动创建 GitHub Release；
> 发布动作由维护者手动执行，避免自动化误发。
