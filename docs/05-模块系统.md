# 05 模块系统

状态：规范基线

## 1. 文件即模块

- 每个 `.sw` 文件是一个模块，模块名由文件路径决定。
- 一个目录内的多个 `.sw` 文件是多个平级模块，通过路径导入。
- 目录 + `sw.toml` 构成包（v0.2 提供包管理；v0.1 只支持文件级模块）。

## 2. 导出

```js
export function greet(name: string): string { ... }
export const Version = "0.1.0";
export class Point { ... }
export interface Drawable { ... }
export struct Config { ... }
export enum Mode { ... }
export type Name = string;
```

- 只有被 `export` 修饰的顶层声明对模块外可见。
- 未导出的顶层声明模块内可见；模块外导入时给出"名称未导出"错误。

## 3. 导入

### 3.1 命名导入

```js
import { greet, Version as SwVersion } from "./util";
```

- 从目标模块的导出中按名导入；`as` 重命名。
- 导入的名字在当前模块内是常量绑定，不可重新赋值。

### 3.2 命名空间导入

```js
import * as util from "./util";
util.greet("Sw");
```

### 3.3 仅执行导入

```js
import "./startup";
```

仅加载并执行该模块的顶层初始化，不引入名字。

### 3.4 标准库

```js
import { println } from "std/io";
import * as fs from "std/fs";
```

- `std/...` 路径指向随 SDK 分发的标准库；标准库模块的身份不依赖安装路径。

## 4. 路径解析

- 相对路径以当前文件所在目录为基准，`"./foo"` 解析为 `foo.sw`；可省略 `.sw` 后缀。
- 禁止 `../` 越出包根目录（v0.2 包内规则）。
- 支持循环导入（A 导入 B、B 导入 A）：加载期先注册模块和顶层占位符，随后统一
  finalize、检查和 MIR 降级；循环双方可调用彼此导出的函数。

## 5. 可见性

- 模块级：`export` / 不写（私有）。
- 类成员：`public`、`private`、`protected`、`internal`。
  - `private`：仅本类可见。
  - `protected`：本类与子类可见。
  - `internal`：本模块内可见。
  - `public`：所有模块可见；默认 `public`（JS 风格）。
- 字段默认可变；`const` 字段只读。

## 6. 当前构建缓存

- 编译器会把本次编译生成的模块对象写入 `.swcache/obj/`，作为链接阶段的工作目录。
- 当前每次构建仍会重新执行模块加载、语义分析和 Cranelift 代码生成；尚未实现基于模块接口
  指纹的增量失效与跨构建复用。

## 7. 明确不支持

- 默认导出 / 默认导入
- CommonJS、`require`
- 动态导入
