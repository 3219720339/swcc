# 00 设计目标

## 1. 定位

Sw 是一门**静态强类型、面向本机程序**的编译型语言，表层语法刻意接近 JavaScript/TypeScript，让熟悉 JS 的开发者几乎零学习成本。

它不做动态类型，不做隐式类型转换，不做自动分号插入。JS 的"表面手感"、静态语言的"确定性和性能"，是本语言的两个支柱。

## 2. 核心目标

1. **跨平台**：Windows / Linux / macOS 的 x64 与 arm64，同一份源码直接编译运行。
2. **自包含工具链**：编译器分发物是一个解压即用的包，用户**不需要**安装 Clang、LLVM、Visual Studio 或任何第三方编译器。
3. **JS 风格语法**：`let/const`、`function`、`class`、箭头函数、模板字符串、`import/export`、`switch`、`?.`/`??`。
4. **本机性能**：编译为本机机器码，无解释器、无虚拟机。
5. **增量友好**：稳定的 MIR 边界 + 模块接口缓存，改一个文件只重编译受影响部分。

## 3. 语法风格约定（JS 兼容面）

以下 JS 语法在 Sw 中**保持原样可用**：

```js
let count: int = 10;
const name = "Sw";
const message = `count = ${count}`;

function add(a: int, b: int): int {
    return a + b;
}

const double = (x: int): int => x * 2;

if (count > 0) { ... } else { ... }
while (count > 0) { count--; }
for (let i = 0; i < 10; i++) { ... }
for (const item of items) { ... }

switch (code) {
    case 0: ...
    default: ...
}

import { println } from "std/io";
import * as fs from "std/fs";
```

与 JS 的差异：

- 静态强类型：变量、参数、字段必须有可确定的类型（可推导时省略标注）。
- 显式分号：语句结束必须写 `;`，不做自动分号插入。
- `null` 是唯一的空值；没有 `undefined`。
- 没有 `===`/`!==`：类型系统保证 `==`/`!=` 总是类型安全的。
- 没有动态对象 `{ }` 字面量自由飞翔：对象字面量必须能确定目标类型（见 03 类型系统）。
- 不支持默认导出、CommonJS、`var`。

## 4. v0.1 范围（明确做）

- 数值类型、bool、string、char、`T[]`、`T?`、`ptr<T>`
- `let/const`、函数、箭头函数、默认参数、顶层重载
- 控制流：`if/else`、`while`、`for`、`for...of`、`switch`、`break/continue/return`
- `struct`、`enum`（无载荷）、`class`（含继承、接口、虚方法）、`this/super`
- 泛型函数/结构体/类/接口 + `where` 约束
- 字符串插值、数组字面量、`new` 表达式
- 模块：文件模块、命名导入、命名空间导入、`export`
- 错误处理：`throw`、`try/catch/finally`、`defer`
- `extern c function` C ABI 互操作
- 自包含后端闭环：MIR → Cranelift → 目标文件 → lld 链接 → 本机程序

## 5. v0.1 明确不做（后续版本）

- 动态类型、`any`、隐式转换、`var`、`undefined`
- 自动分号插入
- 带载荷枚举与模式匹配（`match`）
- 解构赋值与 rest（`let { a, b } = obj`）
- 弱引用 `weak<T>`、循环引用自动回收
- C++ 头文件导入、本机 C/C++ 源码编译（需要外部 clang，仅作为可选扩展）
- 动态库/静态库导出、Windows 资源编译
- 垃圾回收器
- 协程、线程、异步 I/O

## 6. 技术路线

```text
Sw 源码
  → 词法分析（纯 Rust）
  → 语法分析 → AST（纯 Rust）
  → 名称解析与类型检查（纯 Rust）
  → MIR（稳定边界）
  → Cranelift 进程内生成机器码
  → object 库写出 ELF / COFF / Mach-O 目标文件
  → lld 内嵌链接（自带运行时 + CRT/系统库）
  → 本机可执行文件
```

整个编译过程不调用任何外部编译工具。Cranelift 优化能力弱于 LLVM，但 v0.1 优先保证"零依赖分发 + 正确性 + 迭代速度"；后端边界保持可插拔，将来可增加可选 LLVM 后端。

## 7. 分发模型

```text
swc-<版本>-<平台>.zip
├─ bin/swc
├─ lib/sw_runtime.a        （按目标平台预编译的 Rust 运行时）
├─ lib/<目标>/libc/...     （Windows 为 MinGW-w64 运行库）
└─ stdlib/                 （Sw 标准库源码 + 接口缓存）
```

运行时按目标平台在 CI 预编译好随包分发；终端用户只下载自己平台的一个包。
